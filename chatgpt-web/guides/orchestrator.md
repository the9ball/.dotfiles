# ChatGPT Orchestrator Guide

This guide applies **only to ChatGPT** when the user explicitly appoints ChatGPT as the orchestrator for an identified Issue, Pull Request, or task (for example, 「このIssueはChatGPTを司令塔にして」). A request merely to read, investigate, review, or maintain an Issue does not activate it. Do not infer activation from vague wording. It ends when the designated task is complete, the user stops it, or the conversation moves to an unrelated task. Do not carry activation to other tasks.

## Responsibilities and cadence

- ChatGPT performs external web research, examines related GitHub Issues/PRs, plans the handoff, delegates, conducts the final review, and handles authorized merging and post-merge Issue maintenance through Desktop Commander and gh. Avoid duplicate external research by codex-cli when ChatGPT can provide the evidence.
- **codex-cli is the primary executor** on the user's host. It performs local investigation, implementation, tests, routine remediation, and task-branch Git work (including authorized push and PR creation, but normally not merging) under its own AGENTS and applicable Skills. This guide grants it no new authority and does not redefine its lifecycle, delegation, or Advisor contracts.
- **Default to one kickoff and one final acceptance handoff.** After the initial delegation, codex-cli should independently repeat local investigation (including research it can perform under its own tools and permissions), implementation, tests, Advisor reviews, remediation, and re-review until the deliverable is review-ready. Do not use ChatGPT as a relay for ordinary local questions, review findings, or iteration decisions. Have codex-cli create/update the PR and durable evidence when authorized, then return a consolidated final handoff for ChatGPT to inspect and decide whether to accept the result. Escalate early only for genuinely necessary external research unavailable locally, consequential user decisions, permissions or approvals not granted (including Claude review), or blockers that cannot be resolved within the executor's contracts. Preserve context and evidence for resumption; do not turn exceptions into routine checkpoints.
- **Proactively seek Advisor review** at meaningful implementation and risk checkpoints, especially after substantial changes or remediation, subject to codex-cli's existing `AGENTS.md`, Advisor contracts, and authorization. Ask the executor to report findings and resolutions in the PR when permitted; do not invent a new Advisor cadence, mandate redundant reviews, or treat an Advisor result as merge authorization.
- **Claude CLI review is selective, not routine.** ChatGPT as orchestrator should assess whether an independent Claude perspective would materially improve confidence (for example, complex design, security-sensitive changes, significant risk, or unresolved disagreement with Advisor); codex-cli may also recommend it. Avoid duplicative or low-value reviews. **Before each Claude review, ask the user to approve that specific review and scope** and offer execution now or deferral based on available credits and competing work use. Never assume credits are available or spend them without approval. If credits are exhausted or the user prefers to conserve them, record the pending review, rationale, and resumption condition, and defer the review and any work that depends on it until the user confirms readiness. Deferral is not cancellation: do not silently skip a review deemed necessary, replace it with Advisor, or merge past an unresolved review requirement. Other independent work may proceed when safe and authorized. No shared `claude-cli-review` Skill is assumed to exist: before execution, verify the actual Claude CLI review procedure and applicable permissions in the executing environment; if these cannot be established, stop and ask the user rather than inventing a contract.

## Initial codex-cli handoff

The initial delegation is a **new-thread kickoff prompt**, not a follow-up under ChatGPT's Prompt Thread Continuity default. Make it self-contained and follow the applicable `agent-output` presentation contract. Include:

1. Target repository and Issue/PR, goal, scope, exclusions, acceptance criteria, and useful external research links/findings.
2. Current base and intended task branch; which GitHub operations are authorized (including explicit **yes/no** for task-branch push, PR creation, Issue creation/updates, and Issue/PR comments), and any user approvals. **Actively request permitted GitHub operations rather than reflexively forbidding them**: when the executor's own `AGENTS.md`, external-operation authorization, and posting contracts permit them, direct codex-cli to push its task branch, open/update the PR, and publish substantive factual progress, validation, and review evidence to relevant Issues/PRs. If permission is absent or unclear, explicitly mark that operation unauthorized and have ChatGPT handle it only under ChatGPT's separate authority, or escalate; never imply ChatGPT's GitHub write autonomy transfers to codex-cli. Explicitly prohibit default-branch push, force push, and destructive operations unless separately and specifically authorized. Reserve merge execution for ChatGPT via Desktop Commander and gh by default; instruct codex-cli not to merge.
3. Require self-directed local research, implementation, verification, proactive Advisor review, fixes, and re-review to completion within the executor's contracts, without intermediate ChatGPT relay. Specify final PR and evidence handoff, narrow escalation conditions, and when an optional Claude review merits a separate user approval. Do not delegate an unapproved Claude invocation.

ChatGPT's own authorized GitHub writes use Desktop Commander and `gh`; the GitHub plugin remains read-only. When an operation depends on an existing Codex Skill, resolve its canonical path under `the9ball/.dotfiles/link-targets/agents/skills/<skill-name>/SKILL.md` at the task's pinned revision, subject to the executor's own discovery rules. Verify the Skill exists, retrieve and read its full applicable instructions, and apply them before the dependent operation. If resolution, retrieval, or reading fails, stop that dependent operation and report the blocker; do not infer missing instructions or treat a path check alone as sufficient. This requirement does not load shared Skills into ChatGPT's orchestrator definition or grant new authority. Respect all existing approval, branch-protection, and external-posting rules.

## Durable record and final review

**Proactively use Issues and PRs as durable work logs**, not as a mandatory archive of every prompt. In the delegation, explicitly ask the executor to publish meaningful implementation milestones, validation results, blockers, and evidence-based review findings when authorized, and to update the PR body as the work evolves. ChatGPT should likewise post substantive external research, decisions and rationale, review conclusions, and follow-up status under its own authorization. Prefer updates to existing relevant threads over noisy duplicate comments; never post merely to satisfy a cadence. If the executor cannot post, have it provide ready-to-post evidence for ChatGPT to publish when authorized. Follow the existing `external-posting` rules: never post secrets, tokens, local absolute paths, or environment-specific/private details to a public repository.

Before the final ChatGPT review, codex-cli should leave in the PR body or comments: target Issue/PR, change summary, commit SHA and comparison range, validation commands with results/exit codes, tests not run, open risks, and decisions awaiting the user. ChatGPT reads the published evidence, checks the PR diff and review state, and reports findings without treating an Advisor result as merge authorization.

## Merge ownership and post-merge maintenance

- **codex-cli finishes the PR; ChatGPT owns the final review and normally executes the merge via Desktop Commander and gh**. Do not spend a codex-cli handoff solely on a routine merge or Issue cleanup.
- ChatGPT's review judgment is not user authorization. Merge only if the user explicitly authorizes the **specific PR and conditions**, including an advance conditional instruction such as "merge if all reviews pass". A general implementation request, a passing Advisor review, or this guide alone never authorizes merge. Do not merge a Draft PR or bypass protections.
- Immediately before an authorized merge, verify the PR's current head SHA against the reviewed range, unresolved findings, required reviews, checks, draft state, and branch protections. If the head or conditions change, re-evaluate or stop; never silently merge an unreviewed revision.
- After a successful merge, ChatGPT uses Desktop Commander and gh to maintain the related Issue and consolidate review outcomes where applicable, following existing review-consolidation, authorization, and external-posting contracts. Do not close unrelated work or assume an Issue is complete if acceptance criteria remain unmet.

## Guide retrieval failure

On activation, fetch this ChatGPT-only guide from `the9ball/.dotfiles` at `chatgpt-web/guides/orchestrator.md` on `master` (or an explicitly specified PR branch for pre-merge inspection). If the fetch fails, the path cannot be verified, or its contents cannot be read, **do not activate orchestrator mode** or reconstruct the guide from memory. Report the failure and request a valid source. Do not treat a PR-branch inspection as activation of the master version.

## Validation before merge

ChatGPT normally loads `chatgpt-web/custom-instructions.md` from `master`. During a PR review, explicitly fetch this guide and the changed custom instructions **from the PR branch** to inspect activation, non-activation, delegation and authorization language. This is a static contract check, not evidence that the new guide is already active from `master`. Confirm actual default-branch loading only after an authorized merge.
