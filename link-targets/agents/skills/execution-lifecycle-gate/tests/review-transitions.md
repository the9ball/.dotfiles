# Advisor final-assessment regression cases

These nonruntime tabletop fixtures exercise the execution-lifecycle-gate contract. They do not establish host behavior, review quality or cost savings. Apply the fixed source contract and its existing approval/stop rules; do not use an edited contract to approve its own introduction. Record the evaluated candidate identity and each case's actual outcome separately from this expected-outcome table.

| Case | Fixed inputs / transition | Expected outcome |
| --- | --- | --- |
| F1 counterexample | Independent review returns findings in epoch 1; substantive correction starts epoch 2; inherited iterative confirmation returns CLEAR; trailing-whitespace-only normalization is classified preserving. No completed final assessment exists at the source revision. | Final-pass preserving inheritance is blocked. Iterative CLEAR plus a preserving edge does not supply the missing final basis. Complete current-target-confirmation under the applicable contract or obtain current independent review. |
| Partial or incomplete source | Source has only spot CLEAR, slice CLEAR, an unfinished independent review, or independent coverage of only part of the required final scope. | None supplies a completed final assessment for the full candidate. Do not expand scope or promote these results into final-pass preserving evidence. |
| Independent final source | Source has a valid completed independent-current assessment covering the required scope. A same-epoch preserving change has verified identity, delta and edge. | Preserving inheritance may use that source final-assessment record and its independent evidence. Source verdict remains source-bound; all other gates still apply. |
| Conditional final source | An independent anchor plus current Advisor confirmation and every current-target-confirmation requirement already form a valid completed source final basis. A same-tree commit follows. | Preserving inheritance may retain the complete basis and independence lineage. It does not claim current independent review, and the underlying iterative CLEAR alone is ineligible. |
| Inheritance chain | R1 has only iterative CLEAR; edges R1 to R2 and R2 to R3 are preserving. Alternatively, R1 has a valid completed non-inherited final basis and every edge is verifiable. | The first chain cannot launder incomplete evidence. Only the second can supply final-pass inheritance, with source final-assessment and edge lineage retained. Unknown source identity or missing edge blocks passage. |
| Invalidating correction | A completed independent review is followed by a substantive correction, new epoch and current confirmation. | Old gate/verdict is invalidated. Current-target-confirmation requires its complete current proof and independent anchors; incomplete proof blocks passage. Stop before a further invalidating change would start epoch 3. |
| Mode-specific independence | Compare current independent review with unverified isolation; preserving with missing source independence lineage; and current-target-confirmation with verified independent anchors plus explicitly non-independent current confirmation. | The first two are blocked by missing required evidence. The third can qualify when all its remaining requirements are met; do not require or claim destination independent review for it. |
| Finding withdrawal | Current evidence disproves an independent finding; record finding ID, reason, evidence, current Advisor confirmation and unresolved status. The original reviewer is unavailable. | No universal original-reviewer veto. However, a source-contract independent-reconfirmation requirement, open independent-review request, unknown evidence or unresolved issue still blocks passage. |
| First candidate | No applicable exception exists. Alternatively, a named explicit contract permits an exception with complete alternative final evidence and authority to replace the relevant obligation. | First case requires independent review. Second uses only that authorized alternative, preserving remaining gates. A bare exception label, missing evidence or an unaltered mandatory lower bound does not suffice. |
| Advisor correction after code-review | Selected #138 Phase 1/2 completed for R1; final Advisor causes a change to R2. | Reassess #138 coverage and validation for R2, apply its Phase 1/2 rerun rules as needed, then fix the final Advisor candidate. Advisor confirmation alone cannot validate the old Clean result for R2. |
| Uncommitted input | Immutable capture is revalidated. One request declares a complete bounded excerpt plus all necessary context/dependencies; another declares full-file mode but embeds only part. | The first can supply sufficient reading evidence under advisor-review. The second is NEEDS_EVIDENCE. Capture mutation invalidates the capture; neither snapshot nor live path becomes a retrieval reference. |
| Requests and stopping | One actor requests re-independent review, a request is unknown/unfulfilled, a third decision checkpoint is needed, or two evidence-based fixes fail for the same problem. | Preserve OR/unknown/request handling and the existing stops. No review-mode label or new gate name resets counters or supplies approval. |
