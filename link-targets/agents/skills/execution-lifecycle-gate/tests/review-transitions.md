# Advisor final-assessment regression cases

These nonruntime tabletop fixtures exercise the execution-lifecycle-gate contract. They do not establish host behavior, review quality or cost savings. Apply the fixed source contract and its existing approval/stop rules; do not use an edited contract to approve its own introduction. Record the evaluated candidate identity and each case's actual outcome separately from this expected-outcome table.

| Case | Fixed inputs / transition | Expected outcome |
| --- | --- | --- |
| F1 counterexample | Independent review returns findings in epoch 1; substantive correction starts epoch 2; inherited iterative confirmation returns CLEAR; trailing-whitespace-only normalization is classified preserving. No completed final assessment exists at the source revision. | Final-pass preserving inheritance is blocked. Iterative CLEAR plus a preserving edge does not supply the missing final basis. Complete current-target-confirmation under the applicable contract or obtain current independent review. |
| Partial or incomplete source | Source has only spot CLEAR, slice CLEAR, an unfinished independent review, or independent coverage of only part of the required final scope. | None supplies a completed final assessment for the full candidate. Do not expand scope or promote these results into final-pass preserving evidence. |
| Independent final source | Source has a valid completed independent-current assessment covering the required scope. A same-epoch preserving change has verified identity, delta and edge. | Preserving inheritance may use that source final-assessment record and its independent evidence. Source verdict remains source-bound; all other gates still apply. |
| Conditional final source | An independent anchor plus current Advisor confirmation and every current-target-confirmation requirement already form a valid completed source final basis. A same-tree commit follows. | Preserving inheritance may retain the complete basis and independence lineage. It does not claim current independent review, and the underlying iterative CLEAR alone is ineligible. |
| Inheritance chain | R1 has only iterative CLEAR; edges R1 to R2 and R2 to R3 are preserving. Alternatively, R1 has a valid completed non-inherited final basis and every edge is verifiable. | The first chain cannot launder incomplete evidence. Only the second can supply final-pass inheritance, with source final-assessment and edge lineage retained. Unknown source identity or missing edge blocks passage. |
| Invalidating correction | A completed independent review is followed by a substantive AI correction, new epoch and current confirmation; no user rejection intervenes. | Old gate/verdict is invalidated. Current-target-confirmation requires its complete current proof and independent anchors; incomplete proof blocks passage. Stop before the AI counter would reach its third counted epoch, independently of epoch identifiers. |
| Mode-specific independence | Compare current independent review with unverified isolation; preserving with missing source independence lineage; and current-target-confirmation with verified independent anchors plus explicitly non-independent current confirmation. | The first two are blocked by missing required evidence. The third can qualify when all its remaining requirements are met; do not require or claim destination independent review for it. |
| Finding withdrawal | Current evidence disproves an independent finding; record finding ID, reason, evidence, current Advisor confirmation and unresolved status. The original reviewer is unavailable. | No universal original-reviewer veto. However, a source-contract independent-reconfirmation requirement, open independent-review request, unknown evidence or unresolved issue still blocks passage. |
| First candidate | No applicable exception exists. Alternatively, a named explicit contract permits an exception with complete alternative final evidence and authority to replace the relevant obligation. | First case requires independent review. Second uses only that authorized alternative, preserving remaining gates. A bare exception label, missing evidence or an unaltered mandatory lower bound does not suffice. |
| Advisor correction after code-review | Selected #138 Phase 1/2 completed for R1; final Advisor causes a change to R2. | Reassess #138 coverage and validation for R2, apply its Phase 1/2 rerun rules as needed, then fix the final Advisor candidate. Advisor confirmation alone cannot validate the old Clean result for R2. |
| Uncommitted input | Immutable capture is revalidated. One request declares a complete bounded excerpt plus all necessary context/dependencies; another declares full-file mode but embeds only part. | The first can supply sufficient reading evidence under advisor-review. The second is NEEDS_EVIDENCE. Capture mutation invalidates the capture; neither snapshot nor live path becomes a retrieval reference. |
| Requests and stopping | One actor requests re-independent review, a request is unknown/unfulfilled, a third decision checkpoint is needed, or two evidence-based fixes fail for the same problem. | Preserve OR/unknown/request handling and the existing stops. No review-mode label or new gate name resets counters or supplies approval. |
| User rejection | After detailed review, the user requests an in-scope candidate correction. | Reset AI correction and failed-fix counters and checkpoint allowance; correct, verify, autosquash, repeat detailed review, then user review. Epoch identifiers keep advancing. |
| Bare continuation | After a counter stop the user only authorizes continuation. | Preserve all counters; this is not candidate rejection and supplies no missing review or external authorization. |
| Repeated AI failure | Two evidence-based fixes to the same Advisor or Codex finding fail, or another AI invalidating correction would reach the third counted epoch. | Stop and report; trigger 7 and one-shot delegation do not lift the limit. |
| Scope-changing rejection | User feedback changes scope or design. | Return to plan creation, review, and approval before affected implementation; do not substitute detailed review for plan approval. |
| Post-review autosquash | Corrections from detailed review are verified and autosquashed. | Equal pre/post trees are preserving; obtain current detailed-review evidence before user review. Unequal trees stop execution and invalidate the gate. |
| Result-only plan | Investigation or re-verification produces results without repository changes. | Review fixed results and record completion; no commits, slices, autosquash, or commit map. Report discovered defects; fix them under a separate plan. |
| Mandatory review | A plan meets any mandatory trigger, including shared-system load. | Advisor and Codex review cannot be lightened through the low-risk read-only exception. |
| Planned trigger under delegation | One-shot scope itself meets a mandatory trigger, with all runtime checkpoints resolved. | With repository changes, normal PASS then authorized commit/push, stopping before PR/completion operation; without changes, stop before execution. |
| Unnamed external operation | A one-shot instruction names PR creation but another external write becomes necessary. | Stop that write, finish independently authorized work, and report; the plan/completion label does not authorize it. |
| No fabricated authorization | One-shot instruction skips plan approval and user review. | Record NONE/SKIPPED and the explicit instruction; create neither USER_AUTHORIZED nor PASS_WITH_USER_AUTHORIZATION. |
| Worktree needed | One-shot execution needs a worktree with no separate creation approval. | Stop before creation; one-shot delegation and a plan proposal alone do not authorize it. |
| Rewrite exclusion | Target tree/index is dirty or has untracked files, commits are published, the task ledger is absent, or remote-tracking-ref freshness is doubtful. | Do not use the unpublished-task-commit exception; require explicit authorization under the normal route. |
| New runtime trigger | A newly arising trigger 1–5 decision, risk acceptance, missing evidence, or Advisor REQUIRES_USER_DECISION occurs during one-shot work. | Stop the affected part before the decision/operation, complete independent work, and report; no PASS. The planned-trigger push continuation cannot override this stop. |
| Codex unavailable | Codex cannot run during one-shot execution; all other gates and external authorization hold. | Implement, verify, obtain Advisor review, commit and push under the narrow pending-Codex continuation; stop before completion operation and let the returning user decide wait/omission. Never waive findings or claim completed Codex review. |
| Estimate under delegation | Excess is reason (a)/(b) versus reason (c) or scope expansion. | Continue within scope and report (a)/(b); stop the affected part for (c)/expansion. Missing permission or risk decisions still stop. |
| Lighter one-shot review | Coordinator proposes lighter reviews during one-shot work. | Do not lighten; only an eligible plan and user approval can establish lighter reviews outside one-shot delegation. |
| New file through completion | One-shot PR instruction, valid appointment, no mandatory triggers or unresolved decisions, in-scope new file, successful verification and AI reviews, and separate external authorization. | Create the file, verify, organize commits and pass the gate; proceed through authorized push and the current Draft/ready PR sequence without routine user checkpoints. |
| Post-stop candidate feedback | After a stop outside one-shot delegation, compare an instruction correcting candidate content with “continue” or ambiguous feedback, for both effective_user_review=REQUIRED and NONE. | The content correction is a substantive rejection: reset the AI correction counter to 1, same-finding failures to zero, and the two-checkpoint allowance. Bare or ambiguous continuation does not reset. No reset occurs while one-shot delegation skips user review. |
