# Datadog Read-only Delegation

Datadogの参照作業を、必要なスキルとMCPの使い方を調べたうえで安全に実行するためのルーティングスキルです。

## Routing

まず依頼が単発か、継続的な調査かを判定する。

- 単発のメトリクス、ログ、ダッシュボード、ドキュメント参照は、原則として読み取り専用のサブエージェントへ委譲する。
- 直近の結果を踏まえて複数回クエリを調整する、複数のDatadogデータを横断して調査する、または会話中に継続的な参照が予想される場合は、メインスレッドで関連スキルとMCPの使い方を読み込み、そのまま実行する。委譲による文脈分断と往復を避ける。
- 同じ目的・対象・権限範囲の読み取り調査をすでに担当している既存のエージェントまたはセッションがあり、それを再利用できる場合は、新規に作らず再利用する。再利用できるかどうかは実行環境によって異なるため、可能な手段がないなら新規に委譲してよい。
- サブエージェントが必要な権限、認証、ユーザー承認、書き込み操作を求めた場合は、そこで停止してメインスレッドへ返す。

## Skill and tool selection

- ログの検索・集計・コスト上の注意が必要なら `dd-logs` を読む。
- Datadogの機能や制限、権限仕様を確認するなら `dd-docs` を読む。
- `dd-pup` はPup CLI用の手順であり、MCPの認証設定とは別管理である。PupでSATを使う場合は、Pup側にも `DD_ACCESS_TOKEN` などの設定が必要になる。MCPを介した参照では、接続済みのDatadog MCPの読み取りツールを優先する。
- SATで接続されたDatadog MCPを使う場合は、利用可能なMCPの読み取りツールから選ぶ。
- スキルの説明だけでツールの入力や出力が確定しない場合は、利用可能なツール定義と実際の応答を確認してから呼び出す。

## Authorization and privacy

- このスキルは読み取り専用。Datadogの設定、権限、認証、モニター、ダッシュボード、ワークフローなどを変更しない。
- SATの値を、表示、要求、ファイル保存、委譲プロンプトへの埋め込みをしない。これは置き場所を問わない。環境変数(`DD_ACCESS_TOKEN` など)、MCP設定ファイルの `Authorization` ヘッダ、その他の設定ファイルのいずれに入っていても同じ扱いとする。
- クエリには必要最小限の期間、粒度、件数上限を指定する。ログ本文、ホスト名、メールアドレス、ユーザーIDなどは、回答に不要なら返却・再掲しない。
- 外部への書き込みや破壊的操作が必要になった場合は、読み取り調査を続けず、ユーザーの明示的な承認を求める。

## Delegation prompt

サブエージェントへ委譲する場合は、親スレッドを読めると仮定せず、次を明示する。

- 調査対象、クエリ、期間、粒度、件数上限
- 必要なスキル(`dd-logs`、`dd-docs` など)を先に読むこと
- SATの値を扱わず、利用可能なDatadog MCPの読み取りツールを使うこと
- 書き込み、権限変更、認証変更、追加タスク作成をしないこと
- 実行したクエリ、対象期間、結果の要約、件数・単位、エラー、未確認事項を返すこと
- 生ログや機密情報は必要最小限にし、可能なら集計値にすること

## Main-thread verification

サブエージェントの報告だけで完了扱いにせず、メインスレッドで依頼内容と結果の対応、期間・単位・クエリ、権限エラーの有無を確認する。事実、推測、未確認事項を分けて最終回答する。
